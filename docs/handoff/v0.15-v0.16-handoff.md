# v0.15.0 & v0.16.0 Handoff — Template Studio, 20 Recipes & Board Intelligence

This handoff documents everything built, tested, and verified after `v0.14.0` across two releases, both merged to `main`:
- **`v0.15.0`** (PR #75 — **merged to `main`**, 7/7 CI checks green): Full Template Studio, 20 Guided Recipes Gallery, inline attribute/time simulator, and Sandbox `time`-at-entity trigger fix.
- **`v0.16.0`** (PR #76 — **merged to `main`**, 7/7 CI checks green): Board Intelligence & Safety Net (Never-Fired / Quiet Automations, Impact Inspector, Plain-English Version Diffs, Share-a-Function Anonymized YAML Package Export, and Self-Running Checks + Home Assistant Repairs).

> **Design North Star preserved throughout:** *"It's still Home Assistant, made visible and testable."* Zero external Python dependencies, zero external network calls, zero ingress sessions/cookies, and 100% standard Home Assistant entities, config flows, and Repairs.

---

## 1. v0.15.0 — Template Studio & 20 Guided Recipes (PR #75)

### New & Updated Modules
- **`frontend/lib/template_studio.js`** (pure ES module):
  - **5-goal big-picture → small-picture wizard** (`TS_GOALS`, `TS_RECIPES`, `17` template helper recipes):
    - *Yes or No* (`tpl_any_all`, `tpl_logic` multi-entity AND/OR, `tpl_threshold`, `tpl_time_window`)
    - *A Number* (`tpl_count` incl. area/label/domain scope, `tpl_math`, `tpl_scale`, `tpl_duration`, `tpl_batteries`)
    - *A Time, Schedule, or Countdown* (`tpl_sun_offset` with after-event rollover protection & `device_class: 'timestamp'`, `tpl_countdown`, `tpl_duration`, `tpl_time_window`)
    - *Readable Text or Status Label* (`tpl_list_names`, `tpl_fallback`, `tpl_band`, `tpl_attribute` with live entity attribute picker + 0–255 brightness %, `tpl_map_state`, `tpl_custom_msg`)
    - *Understand or Fix an Existing Template* (Explain / Custom mode)
  - **Interactive 32-concept Jinja Guide** (`TS_CONCEPTS`, `TS_HELPERS`): plain-English descriptions, why-you-need-it callouts, live examples, and entity-aware insertion (covering `float`, `int`, `expand`, `selectattr`, `has_value`, `as_datetime`, `as_local`, `timedelta`, `strftime`, `relative_time`, `abs`, `average`, `bool`, `replace`, etc.).
  - **Natural plain-English walkthrough (`explainTemplate`)**: translates Jinja lines, variables, filters, sun/date offsets, and pipelines into readable prose with clickable `? concept` pills and live sub-expression evaluation via `render_template`.
  - **Unavailable-trap linter (`lintTemplate`)**: flags bare `| float`/`| int`, `states.domain.entity.state` access, unguarded string/numeric comparisons, missing `availability` / `has_value()`, and unbalanced blocks, with 1-click fixes.
  - **Context-aware inline simulator analysis (`analyzeSimInputs`)**: distinguishes attribute reads (`state_attr`/`is_state_attr`) from state reads and clock/weekday reads (`now()`, `today_at()`, `weekday()`, `last_changed`).
- **`frontend/ui/studio.js`** (`studio` part, owns `_stu`):
  - Modal workspace accessible from `Recipes → Template Studio…` and from any template helper or templated automation/script box via nodebar **`Template Studio`** (`ts_explain_btn`).
  - Inline "What if…" simulator with entity state presets, dedicated attribute rows (time pickers/presets for `sun.sun`/calendar timestamps, `0/50/100%` for brightness, `Missing` test), and simulated clock/weekday overrides via `sbxRewrite` + `render_template`.
  - **Try in sandbox** injects the unsaved virtual Template helper directly into the board Sandbox.
  - **Save** creates/updates a native HA Template `sensor` (with `device_class`, `unit_of_measurement`, `state_class`) or `binary_sensor` via `config_entries/flow` (`template`), labels it into the function, and records `layout.builders[entity_id]` (reopens in its recipe while unchanged; opens in Explain & Inspect once hand-edited).
- **`frontend/lib/builders.js` & `frontend/ui/builders.js`**:
  - Categorized, searchable **All 20 Recipes Gallery** (`17` templates + `1` Notification Builder + `2` Automation recipes: **Left-open / Left-on alert** and **Motion-activated light**).
- **`frontend/lib/sandbox.js`**:
  - Fixed `time`-at-entity trigger flow (`trigger: time` with `at: sensor.<timestamp>`, `input_datetime.*`, or `{ entity_id, offset }`) in `_armTime()`, `_fire()`, `_changed()`, and `userRun()` so Sandbox flow playback starts on the trigger entity box instead of the automation box.
- **`custom_components/functions_board/sources.py` & `websocket.py`**:
  - Added optional `include_templates: bool = False` on `functions_board/sources` exposing `state`, `availability`, `icon`, and `attributes` templates (including time-only templates) defensively.
  - Fixed `test_template_sources_with_availability_and_time_only` teardown in `tests/backend/test_sources_and_diagnostics.py` by removing the `now()` template entity in a `finally:` block so `TrackTemplateResultInfo._setup_time_listener` leaves no lingering timer.

## 2. v0.16.0 — Board Intelligence & Safety Net (PR #76)

### Feature Breakdown & Files

1. **Never-Fired / Quiet Automations**
   - `frontend/lib/wiring.js`: `QUIET_DAYS = [30, 90, 365, 0]`, `findQuietAutomations(members, ctx, { days, now, dismissed })`. Filters to enabled, healthy automations (`state === 'on'`, not disabled) whose `last_triggered` is `null` or older than `days`. Dismissals use key `q|<entity_id>` in `layout.dismissed` and are excluded from `splitDismissed`'s 24h auto-forget `covers` predicate.
   - `frontend/ui/problems.js`: Renders a calm `.pqchip` in the header (strictly separate from `.pchip` error/warn badge and `_noteProblems` list counts) and a dedicated `.pquiet` section in the Problems drawer with `30d` / `90d` / `365d` / `Never` pills (persisted in `ui.quietDays`), Jump, Turn off, Dismiss, and Ignore buttons. Quiet rows use `.pqrow` (never `.prow`) so existing problem assertions stay cleanly separated and dark/light contrast passes axe-core WCAG 2.2 AA.

2. **Impact / "Where is this used?" Inspector**
   - `frontend/ui/tools.js` (`_openImpact`, `_impactOpenHA`, owns `_impactTok`) & `frontend/board-core.js`:
   - Read-only **`Where used`** (`data-act="impact"`) button in `_renderNodebar()` for any entity, helper, automation, script, scene, or device.
   - Scans across the entire HA instance: board Functions carrying its label, all automations & scripts via `analyze()` (displaying `trigger` / `condition` / `action` / `calls` / `template` role pills and expanding device → device entities), Groups & Scenes (`attributes.entity_id`), Derived Helpers (`functions_board/sources`), and Node-RED flows (`_nrState()`). Includes clickable jump chips to other functions or `Open in HA`.

3. **Plain-English Version Diffs**
   - `frontend/lib/ver_diff.js`: `fmtDiffDur`, `diffConfigs(before, after, kind, opts)`, `diffSnapshots(fromSnap, toSnap, opts)`. Translates config diffs into human sentences (`"Waits 15 min instead of 10 min"`, `"Run mode changed from single to restart"`, trigger/condition/action additions, removals, disables, parameter changes, and helper option/duration/setting changes).
   - `frontend/ui/versions.js` (owns `_verCmp`):
     - Adds **Compare** (`data-act="ver-compare"`) on every version row and version tab banner, opening a modal to compare any saved version against **Current live function** or any other saved version (`_verChange` handles `<select name="vcmp">`).
     - Embeds the plain-English diff summary inside `_verRestoreDlg()` (`Make active` confirmation dialog) via `plan.plainDiff`.

4. **Share a Function — Anonymized YAML Package Export**
   - `frontend/lib/share.js`: `PackageAnonymizer` and `exportFunctionPackage(pkg, { anonymize })`. Exports a function's automations, scripts, UI helpers (`input_*`, `counter`, `timer`, `schedule`), and template helpers into a single HA YAML package (`automation:`, `script:`, `<helper>:`, `template:`).
   - Anonymization is **on by default**: consistently replaces entity IDs (`cover.cover_1`, etc., preserving generic services and `sun.sun`), area/floor/label/device IDs (including inside Jinja `area_entities()`/`label_entities()`), known friendly names, MQTT custom topic segments, URLs (`[url]`), emails (`[email]`), IPs (`[ip]`), MACs (`[mac]`), phones (`[phone]`), long tokens, and free-text notification copy — plus a placeholder-only checklist in the YAML header comment (zero real names leaked).
   - `frontend/ui/functions.js` (owns `_shareData`) & `frontend/ui/list.js`: Adds **Share as YAML package…** (`fnm-share`) to the function `⋮` menu with live preview, anonymize toggle + warning when unchecked, Copy YAML, and Download `.yaml`.

5. **Self-Running Checks + Home Assistant Repairs**
   - `custom_components/functions_board/check_runner.py`: `evaluate_check`, `_SimEngine`, `CheckRunner`.
     - Automatically runs saved checks on HA startup (`EVENT_HOMEASSISTANT_STARTED` or `CoreState.running` if checks exist), `automation_reloaded`, `script.reload`, and `functions_board/set_checks` (debounced, with timer + task cleanup on `EVENT_HOMEASSISTANT_STOP` and `async_unload_entry` so `verify_cleanup` sees zero lingering timers/tasks).
     - Evaluates supported ops (`set`, `advance`, `next`, `run`, `event`, `mqtt`, `ha`, `webhook`, `tag`) on isolated virtual state using HA's own `Template` renderer with virtual `states`/`is_state`/`state_attr`/`is_state_attr`/`has_value`/`now` bindings.
     - Honestly marks browser-only/unsupported checks (`press`, `zwave`, `behave`, `calendar`, `say`, interactive `answers`, `device` triggers/conditions/actions, `use_blueprint`, `wait_for_trigger`/`wait_template`/`parallel`) as `status: "board_only"` (`"Run in board"`) rather than false-failing.
     - Creates/updates native HA Repair issues (`ir.async_create_issue`, `translation_key="check_failed"`) for failing checks and auto-deletes them once fixed or removed.
   - `custom_components/functions_board/websocket.py`: Added admin-only `functions_board/check_results` and `functions_board/run_checks`.
   - `custom_components/functions_board/strings.json` & `translations/en.json`: Added `issues.check_failed` strings.
   - `frontend/ui/problems.js` (owns `_bgChecks`) & `board-core.js`: Loads `functions_board/check_results` on open and `check_results` subscribe events, rendering `"Run in board"` / background status indicators in the saved checks list.
